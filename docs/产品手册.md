## 1. 项目速览

| 项 | 内容 |
|---|---|
| 是什么 | 公网部署的 Web 应用：上传字幕 → 调用用户自备的 OpenAI 兼容大模型翻译 → 生成双语字幕 → 按媒体服务器命名导出 |
| 范围 | v1 仅处理**字幕文本**（SRT），不处理视频/语音识别/转码/内嵌 |
| 技术栈 | Next.js 15（App Router）+ TypeScript + React 18 + Tailwind CSS 3 + Zustand 5 |
| 后端 | **唯一**一个无状态转发路由 `src/app/api/translate/route.ts`；无数据库、无账号 |
| 模型协议 | OpenAI 兼容 Chat Completions，保留供应商自己的 base path |
| 密钥 | 用户 UI 手填 → 当前页面内存（勾选记住设备才写 localStorage）→ 服务端转发；不进源码 |
| 测试 | Vitest，覆盖 core、设置迁移、代理与客户端、队列竞态；数量以 npm test 为准 |
| 部署 | 宝塔「Node 项目」+ PM2 + Nginx 反代 + HTTPS + 网站密码 |
| 代码量 | `src/` 约 2.5k 行 |

**心智模型**：本质是「纯前端 + 一个转发文件」。前端干所有活（上传、解析、预览/编辑、翻译编排、双语组装、导出），后端那一个文件只为绕开浏览器 CORS 与避免密钥暴露而存在。

## 3. 架构总览

```
浏览器（前端 SPA，几乎所有逻辑）
   │  上传字节
   ▼
[encoding] 探测+解码  →  [parsers/{srt,ass,vtt,lrc}] 解析  →  [cleanup] 源字幕清理 + [detect] 语种判定
                                             ↓
                                    SubtitleDocument（时间统一毫秒，格式无关）
                                             ↓
                       [glossary] 分批生成候选 → 人工审核 → 当前文件已确认译名
                                                      │
                          用户配置/参数（Zustand store，持久化）
                                                      │
   客户端编排（lib/useTranslator → core/translator/engine）
   逐批 → fetch('/api/translate') ───────────────┐
                                                  ▼
                              [api/translate/route.ts]（唯一后端，无状态转发）
                                                  ▼
                                       用户的 OpenAI 兼容模型 API
                                                  │ 返回 JSON
   ◀──────────────────────────────────────────────┘
   对齐校验/缺失重试 → 回填 translatedText 到 Document →（可选）[qa] 译文体检
                                                      │
[bilingual] 双语组装(+合并多行/配色) → [serializers/{srt,ass}] → [naming] 文件名 → 浏览器下载
                                                      │
                               批量队列：逐个文件跑完上面整条链 → [zip] 打包下载
```

**两条铁律**（设计核心，改动时不要破坏）：
1. **公共中间模型**：所有格式先转成 `SubtitleDocument`（时间统一毫秒）；翻译/双语/样式只认这个模型，与格式无关。新增格式 = 加一对 parser/serializer，引擎与 UI 一行不改。
2. **客户端编排**：翻译循环由浏览器驱动，后端保持无状态。这样进度天然、可取消、可断点续传。

## 5. 公共数据模型（`core/model/index.ts`）

```ts
type SubtitleFormat = 'srt' | 'ass' | 'vtt' | 'lrc';   // 已实现 srt / ass

interface InlineTag { raw: string; offset: number; }   // 抽离的标签 + 在纯文本中的位置

interface SubtitleEntry {
  id: number;            // 稳定顺序索引(从1)，贯穿翻译全程，行对齐的锚
  start: number;         // 毫秒
  end: number;           // 毫秒
  originalText: string;  // 已抽离标签的纯文本（可含 cue 内 \n）
  translatedText?: string;
  tags?: InlineTag[];    // 用于翻译后回填标签
}

interface SubtitleDocument {
  taskId: string;                 // 客户端 UUID
  sourceFormat: SubtitleFormat;
  entries: SubtitleEntry[];
  meta: Record<string, unknown>;  // 存 eol、parseIssues；ASS 阶段存头/Styles
}

interface ParseIssue { line: number; raw: string; message: string; }  // 解析告警(可定位)
```

> `meta` 用于无损保留格式专属信息，保证「解析—序列化」往返不丢东西。SRT 阶段存 `eol`（换行符）与 `parseIssues`。

## 6. 状态管理（`store/index.ts`）

单一 Zustand store，`persist` 中间件持久化到 localStorage（key：`subtitle-translator`）。

### 6.1 状态字段
- **文档类**（仅保留在当前页面，不持久化）：`fileName / detectedEncoding / document / parseIssues / phase / progress / failedIds / translateError / docVersion / cleanupMarks / detectedLang / glossary / glossaryStatus / qaFindings`。
- **队列类**（不持久化）：`queue / queueRunning`。
- **配置类**（持久化）：`apiProfiles / activeProfileId / params / style / assStyle / bilingual / cleanup`。

`phase`: `'idle' | 'parsed' | 'translating' | 'done'`。
`docVersion`: 单调递增计数，翻译过程中节流 `bump` 以触发表格增量重渲（见 §8.6）。

### 6.2 关键 action
- `setDocument / reset / updateTranslation(id,text)`（手动改译文，原地改 entry 并 bump）。
- `selectProfile / setSourceLang / setTargetLang`：**控制条快捷切换，即时生效**。
- `applySettings(snapshot)`：**设置弹窗「保存」时整体写回**（草稿模式，见 §9）。
- `setPhase / setProgress / setFailedIds(ids, error) / bumpDocVersion`。
- `clearTranslations(ids)`（重译前清空）、`restoreExcluded(id?)`（恢复被清理排除的条目）。
- `setGlossary / setGlossaryStatus / setQaFindings / setParams / setCleanup`。
- 队列：`enqueueFiles / updateQueueItem / removeQueueItem / clearQueue / setQueueRunning`。
- 辅助函数：`getActiveProfile(s)`、`newProfile(partial)`、`snapshotSettings(s)`。

### 6.3 持久化与迁移
- 存储版本 3：旧全局生成参数复制到每个旧服务的当前模型。保留显式 none、8192、自定义 prompt 和双轨布局，不根据“等于旧默认”猜测用户意图。
- 新 profile 的 `modelConfigs[model]` 独立保存温度、思考、输出预算、额度字段、输出格式和推理预留。新模型用新默认，不继承其他模型参数。
- 新密钥默认仅页面内存；`rememberKey=true` 才持久化。旧配置保留此前记住设备的行为，可清除或取消勾选。分享始终剔除密钥。
- `snapshotSettings` 深复制嵌套配置，草稿取消不会改动实际 store。迁移幂等；新默认只用于缺失字段/新配置。
- `glossaryCandidates` 与已确认 `glossary` 分开且不持久化，打开新文件/reset清空两者。

### 6.4 任务生命周期
字幕、译文与任务进度仅保留在当前页面，刷新或关闭页面后清空。每次打开直接进入上传界面，不自动存档或恢复任务。当前页面内取消或失败后仍可继续翻译剩余行。

## 8. 关键算法与「坑」

### 8.1 编码探测（`core/encoding`）
流程：字节 → 查 BOM（UTF-8/UTF-16LE/BE）→ 否则 `jschardet` 探测 → `normalizeLabel` 映射成 `TextDecoder` 标签 → 解码 → 去 BOM。
- 解码用浏览器/Node 原生 `TextDecoder`（支持 gbk/big5/shift_jis/utf-16…），**不依赖 iconv-lite 的 Node Buffer**，前后端一致、可单测。
- 置信度 `<0.6` 时 UI 提示手动选编码（`useSubtitleLoader.reloadWithEncoding`）。
- 坑：中文/日文 SRT 常不是 UTF-8（GBK/Big5/Shift-JIS/UTF-16），直接按 UTF-8 读会乱码。

### 8.2 标签保护（`core/tags`）
翻译前用正则 `TAG_RE` 抽离 `<i> </i> <b> <font…> {\anX}` 等，记录 `offset`；翻译纯文本；译完 `reinsertTags` 按 offset 回填（offset 超界则夹紧到末尾，保证整行 `<i>…</i>` 包裹这类常见情况正确还原）。比依赖模型“请保留标签”可靠。

### 8.3 行对齐（`core/translator/engine.ts`，**头号风险**）
模型常合并/拆分行导致译文条数≠原文、时间轴错位。对策：
1. 每条带稳定数字 `id` 以 JSON 数组发出。
2. 固定协议要求返回 `{items:[{id,text}]}`，相同 ID逐条对应；模型仍可能违反，需要校验。
3. `validateTranslationResponse` 先检测重复/非法/额外 ID，冲突项不提交；仅恢复异常目标。格式通过不代表语义正确。
4. 多次重试仍失败 → `failedIds` 标红；任务终止未处理 → `unprocessedIds`。批量部分失败文件不标记全部完成。

### 8.4 引擎其它行为
- **并发**：任务工作队列按 `concurrency` 调度，429后降低并发。
- **重试**：`429 / 5xx / 网络错误` 指数退避（`500*2^n`，上限 15s，带抖动）。
- **跳过**：`originalText.trim()===''` 的空/纯标记行不送翻译。
- **断点续传**：已有 `translatedText` 的条目跳过；中断/失败后再点「继续翻译」只补缺。
- **取消**：`AbortController`，`signal` 透传到 fetch 与 sleep。
- **进度**：`onProgress`（批次/条数/失败数）+ `onEntry`（增量回填）。

### 8.5 合并多行 & 双语布局（`core/bilingual`）
- `assemble(doc, {layout, order, collapseLines}, style?)` → `OutputCue[]`。
- `collapseLines`（默认 true）：把每种语言**内部换行压成一行**（逐行 trim、丢空行、空格连接），避免「原文 3 行 + 译文 3 行 = 6 行」的观看灾难；双语只 2 行，由播放器按宽折行。
- 布局：`dual-entry`(双轨，拆两条同时间轴) / `single-entry`(单轨，一条两行) / `translated-only`(仅译文)。
- 配色：`style.enableSrtColor` 时用 `<font color>` 给原文/译文套色（见 §8.7）。

### 8.6 表格性能（`components/SubtitleTable`，**易踩**）
字幕可达数千条，早期一次性渲染 + 每行一个 `<textarea>` 会卡。现状：
- 每行 `content-visibility:auto` + `contain-intrinsic-size`：**滚动区外的行跳过布局/绘制**。
- 译文列默认是只读 `div`，**点击某行才渲染唯一一个 textarea**（不是每行一个）。
- `Row` 用 `memo`，`onStartEdit/onCommit` 用 `useCallback` 稳定；翻译时 `bump` 节流到 500ms，只有 `translated` 变化的行才重渲。
> 改这个组件时务必保留这三点，否则大文件会重新变卡。

### 8.7 命名与样式
- `core/naming.buildExportName`：`基础名 + 描述符 + 语言码 + .srt`。
  - 描述符：仅译文 `AI{中文}`、双语 `AI{中}{英}双语`（源语言已知）/`AI{中文}双语`（auto）；可被 `translatedLabel/bilingualLabel` 覆盖。
  - `deriveBaseName` 去扩展名与旧的语言/类型尾标（`.chs/.zh/.机翻中英/AI…双语` 等）。
  - 语言映射 `nounOf/charOf/codeOf`，新增语言在此加。
- `core/styling.COLOR_SCHEMES`：5 套方案（译文恒为白色，原文用金黄/墨绿/黛蓝/绛粉等彩色区分）。`DEFAULT_STYLE` 为「不分色」；设置里支持一键调换原文/译文颜色。

## 10. 后端转发路由契约（`app/api/translate/route.ts`）
- `POST`，`runtime='nodejs'`，`dynamic='force-dynamic'`，**无状态**。
- 入参包含 `baseURL/model/messages/authMode/apiKey` 与可选采样、思考、输出格式、一个 token 上限字段；`authMode=none` 时不要求或发送 Key。
- 运行时验证 JSON object、类型、长度、数值范围；正文最多512000字节，上游响应最多2000000字节。
- `buildChatCompletionsUrl` 保留 base path，拼接 `/chat/completions`；拒绝 URL 内账号、查询和片段。
- 默认仅允许内置官方 HTTPS origin；自定义服务由管理员设置 `ALLOWED_API_ORIGINS` 精确放行受信任 origin；所有上游请求拒绝重定向。
- `ALLOW_PRIVATE_ENDPOINTS=true` 仅用于受控本地/私有部署，公网不得无认证暴露。Vercel 上 localhost 不代表用户电脑。
- 只有明确“不支持字段”400才有限降级，共用55秒截止；持续修改 working payload，不删除输出额度。错误响应只回传脱敏 message；白名单回传 Retry-After、request ID 和参数调整说明。
- 客户端返回结构化结果、截断 partialResult 与 usage；本页诊断只存元数据不保存密钥/正文，未知用量不伪造费用。

## 14. 安全模型
- 密钥：手填 → 页面内存（可选记住设备）→ 转发路由穿透；**不硬编码、不进 git、不进前端包**。
- 部署：宝塔**网站密码（Basic Auth）+ 强制 HTTPS**把整站挡在登录后。公网 + 带 key + 无 HTTPS = 不可接受。
- 残留风险：key 留在用户输入它的浏览器里——对个人/小范围 + 密码 + HTTPS 可接受。
- 后续更彻底方案：key 放服务端 `.env`，浏览器全程不接触（见实现规范 §9）。

## 16. 已知限制与后续路线
**当前限制 / 技术债**
- 支持 SRT、**ASS/SSA**、**WebVTT**、**LRC**；VTT/LRC 解析后统一按 SRT 导出（没有 VTT/LRC 序列化器）。
- **不支持直接读视频文件**（内封字幕需先用 ffmpeg/MKVToolNix 抽出）。用 ffmpeg.wasm 在浏览器里读 mkv 文本字幕轨是可行方向，但会引入数十 MB 的 wasm 依赖，未纳入本轮。
- 术语表依赖「首字母大写」这类拉丁文字线索抽取候选，**源语言为中日韩时基本抽不到**，可手动添加。
- 批量队列串行处理（一次一个文件），并发只发生在单个文件内部的批次之间。
- ASS：无损保留 `[Script Info]`/`[V4+ Styles]`/Comment/绘图/卡拉OK 等（原样透传，不翻译）；双语统一走「单条目双行（`\N` 堆叠）」避免同位置 Dialogue 重叠；`\h` 降级为普通空格；行内中段标签按 offset 近似回填。
- ASS 样式：**默认「忠实保留源样式」**——不动源对白字体/字号/颜色，只翻译文字（避免弄崩 fansub 等已排版字幕）。设置里可开「强制统一样式」：剥离源对白装饰类标签（字体/字号/粗斜/颜色/描边），套用「译文大、原文小」。字号以「占视频高度百分比」表达（默认译文 5.5% / 原文 4.2%），按脚本 `PlayResY` 折算 `{\fs}` 等比缩放、跨设备一致；缺 `PlayRes` 时按播放器默认 **384×288** 折算，仅强制样式下注入 384×288。
- ASS 已双语识别：上传时粗判每条是否含中/外两行堆叠，疑似已双语则顶部告警，避免把已翻译字幕再译一遍覆盖原译文（`core/bilingual.looksAlreadyBilingual`）。
- **双语左右/上下分位（dual-entry）、按 Style 落样式留待后续。**
- 表格未做真正的虚拟滚动（用 `content-visibility` 近似），超大文件（上万行）仍可能有滚动条估高跳动。
- 标签回填对“行内多段标签 + 译文长度大变”是近似（offset 夹紧）；整行包裹场景精确。
- `p-limit` 依赖虽在 `package.json`，引擎实际用内置 `pLimit`（保留依赖无害）。
- 存档只保留**最近一份**任务（新文件覆盖旧存档）。

**路线**：按 Style 的 ASS 样式编辑 → VTT/LRC 原格式导出 → 多任务存档 → 从视频文件直接抽取内封字幕（ffmpeg.wasm）→ 服务端密钥存储。

## 2026-11-09 引擎与术语恢复约定

- 输出 `{items:[{id,text}]}`，兼容旧数组；先审查重复/非法/额外 ID，再按唯一目标 ID提交，不按数组位置回填。

- 429同服务冷却并降低任务并发，网络/5xx不拆批；认证或配置错误终止队列、等待在途收敛。返回 `unprocessedIds` 与 `failedIds` 分开。

- 术语只进入候选，整批接受仅新增词，冲突逐条选择；重新生成不覆盖人工表。批量默认不生成候选，开启后当前文件进入review状态等待审核，再使用同一文档继续。
- 任务使用参数快照；清理/重解析在任务运行中禁用；回调检查taskId，旧任务不能污染新文档。
